# PAVO CLUB — موقع نادٍ + لوحة إدارة (HTML / CSS / Vanilla JS + Supabase)

واجهة عامة ولوحة إدارة مستقلة، بلا أي إطار عمل أو خادم خاص. كل البيانات من Supabase (PostgreSQL + Auth + Storage + RLS).
لا توجد بيانات وهمية: إذا كانت القاعدة فارغة تظهر رسائل «لا يوجد…».

## حالة الاختبار (بصدق)
- **اختُبر فعليًا:** ملفات SQL الأربعة نُفذت على PostgreSQL 16 محلي مع بدائل بسيطة لـ `auth` و`storage`؛ واختُبرت سياسات RLS (الزائر لا يرى المسودات ولا يكتب، غير المدير لا يكتب ولا يمنح نفسه دورًا)، ودوال حفظ/نشر/إلغاء نشر التشكيلة، وقيود (11 أساسيًا، لاعب مكرر، قائدان، إحداثيات، نتائج/حالات المباراة، رقم القميص، المنطقة الزمنية). واختُبرت دوال تحويل المنطقة الزمنية في JavaScript.
- **لم يُختبر:** الواجهات في متصفح حقيقي، ولا الاتصال بمشروع Supabase الفعلي، ولا Storage الفعلي (لا مشروع متاح هنا). افحص الواجهة بعد الربط وأبلغني بأي خلل.

## الإعداد
1. أنشئ مشروعًا في https://supabase.com.
2. SQL Editor — نفّذ بالترتيب: `supabase/schema.sql` ثم `policies.sql` ثم `storage.sql` ثم `seed.sql`.
3. **أول مدير:** Authentication > Users > Add user (مع Auto confirm)، ثم نفّذ في SQL Editor:
   `insert into public.user_roles (user_id, role) select id, 'admin' from auth.users where email = 'بريدك';`
   وأوقف التسجيل العام: Authentication > Providers > Email > Allow new users to sign up = OFF.
   (حتى لو تُرك مفعّلًا، الحساب الجديد بلا صف في `user_roles` فلا يملك أي صلاحية كتابة.)
4. **Buckets:** يُنشئها `storage.sql` تلقائيًا: `club-assets`, `player-photos`, `news-images`, `gallery-images` (قراءة عامة بالرابط، والكتابة/الحذف/الاستبدال للمدير فقط، 5MB، JPEG/PNG/WebP). تحقق منها في Storage.
5. **المفاتيح:** افتح `assets/js/config.js` وضع Project URL و Publishable (anon) key من Project Settings > API. **لا تضع** `service_role` أبدًا.
6. افتح `admin/index.html` وسجّل الدخول، ثم: هوية النادي ← الإعدادات (المنطقة الزمنية مثل `Africa/Cairo`) ← البطولات ← اللاعبون ← المباريات ← منشئ التشكيلة.

للتجربة محليًا قدّم الملفات عبر خادم ثابت (ES Modules لا تعمل من `file://`): `python3 -m http.server 8000` ثم http://localhost:8000.

## النشر على GitHub Pages
ارفع المجلد إلى مستودع، Settings > Pages > Deploy from branch (root). في Supabase: Authentication > URL Configuration أضف عنوان الموقع. استبدل `YOUR-DOMAIN` في `robots.txt` و`sitemap.xml`.

## الهيكل
`index/players/player/matches/match/lineup.html` الموقع العام — `admin/*.html` لوحة الإدارة — `assets/css/style.css` + `admin.css` — `assets/js/`: `config.js` (الإعداد)، `supabase.js`، `api.js` (كل الاستعلامات ورفع الصور)، `i18n.js` (الترجمات)، `utils.js`، `ui.js`، `lineup-view.js` (الملعب والخطط)، `app.js` (غلاف الموقع)، `pages/*` (صفحات الموقع)، `admin/*` (لوحة الإدارة).

## قاعدة البيانات
| الجدول | الغرض |
|---|---|
| `club_settings` | صف واحد (id=1): الهوية، الألوان، التواصل، `timezone`، إظهار الأقسام، حدود العرض |
| `players` | بيانات اللاعبين؛ رقم القميص فريد بين **النشطين** فقط؛ `slug` يُولَّد تلقائيًا |
| `competitions` | البطولات |
| `matches` | `club_is_home` يحدد جانب PAVO CLUB (فلا مقارنة نصوص)، `kickoff_at timestamptz`، الأهداف `home_score/away_score` بترتيب المضيف/الضيف، وقيد يمنع نتيجة لمباراة لم تبدأ/مؤجلة/ملغاة ويفرضها للمباشرة/المنتهية/الموقوفة |
| `lineups` | تشكيلة لكل مباراة: **مسودة واحدة + منشورة واحدة** كحد أقصى (`unique(match_id,status)`) |
| `lineup_players` | `player_id` (علاقة حقيقية)، `role` أساسي/بديل، `x_percent/y_percent` (0–100)، `is_captain`، `bench_order`؛ لاعب لا يتكرر، قائد واحد، 11 أساسيًا كحد أقصى |
| `user_roles` | من هو مدير؛ لا يمكن الكتابة فيه من المتصفح |
| `news`, `gallery_items` | الأخبار والمعرض |

ملاحظات تصميم: اتجاه الملعب ثابت — مرمى PAVO CLUB أسفل (y=100) والهجوم لأعلى. المباراة تحتفظ بتشكيلتها التاريخية (حذف لاعب/مباراة مرتبطة بتشكيلة مرفوض، فعطّل اللاعب بدلًا من حذفه). تعديل تشكيلة منشورة يتم على **نسخة مسودة**، وتبقى المنشورة ظاهرة حتى تنشر المسودة (`publish_lineup` تستبدلها ذريًا). النشر يشترط 11 أساسيًا وحارس مرمى واحدًا.
الأهداف في نموذج الإدارة تُدخل كـ«أهداف النادي/أهداف المنافس» وتُحوَّل تلقائيًا إلى مضيف/ضيف. التاريخ والوقت يُدخلان بتوقيت النادي ويُخزَّنان UTC دون تحويل مزدوج.

## حدود وقرارات
- **SEO:** الصفحات تُملأ بـ JavaScript على استضافة ثابتة، فمحركات البحث التي تنفّذ JS تفهرسها، لكن الفهرسة أضعف من الصفحات المولّدة على الخادم، و`sitemap.xml` يضم الصفحات الثابتة فقط. العناوين والوصف و Open Graph تُحدَّث من بيانات النادي الحقيقية.
- الأخبار والمعرض تظهر في الصفحة الرئيسية (لا صفحات مستقلة).
- المباراة «مباشرة» فقط عندما يغيّر المدير حالتها؛ قائمة المباريات تُحدَّث كل دقيقة أثناء وجود مباراة مباشرة.
- لا توجد تشكيلة افتراضية عامة للفريق (اختيارية في المواصفات)؛ كل التشكيلات مرتبطة بمباراة.
- لا أفترض هوية بصرية رسمية: الألوان الافتراضية (أزرق-أخضر «طاووسي» وذهبي) قابلة للتغيير من «هوية النادي».
